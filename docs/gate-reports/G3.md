## Scope delivered
- **Protocol layer** (`lib/protocol/`): executable form of Contract v1.0 — payload grammar, all
  characteristics, JSON encoding/decoding verified against the §8 golden vectors (F1–F7, X1–X6).
- **Device emulator** (`lib/ble/fake/`): deterministic v3-mirroring fake connection (stage
  thresholds, two-setpoint hysteresis, display-minutes logic as doc-documented) with per-tick
  encode→decode round-trips; auto `time`-sync on connect; drives the whole app without hardware.
- **Data layer** (`lib/data/`): Drift DB with three time tiers (raw 1 Hz `raw_samples`,
  `minute_aggregates`, `hour_aggregates`), `HistoryCompactor` retention 24 h / 7 d / 90 d
  (D-012), `HistoryRepository` (window floor + per-bucket points incl. gaps, coverage, stage
  distribution), `filter_health` (load- vs hour-budget model + reset-aware projection),
  settings persistence, alert scheduler (once-per-day while connected), notification plumbing
  (v22 API; permission prompt deferred to Phase 4 first-run).
- **UI** (`lib/features/`): 5-tab shell (IndexedStack), dashboard + system LCD-mirror page,
  history screens (day/week/month fl_chart + stage donut + coverage), filter page (reset
  button Phase-5-gated, D-010), device page (emulator status, demo Seed-7-days / Clear-history).
- **Pipeline**: `RecordingService` boots on app start — state-watch → recorder start/stop,
  60 s compaction passes, 5 min alert evaluations while connected.

## Implementation notes worth remembering
- Non-autoincrement PK columns arrive in drift `Companion.insert` as optional `Value<T>` —
  wrap values in `Value()` (D-016).
- Riverpod 3: `AsyncValue.value` is nullable; no `valueOrNull` (D-016).
- `RecordingService.dispose` must stay synchronous: widget tests verify no pending timers
  immediately after tree disposal; an `await` boundary leaks the recorder's flush timer.
- Widget tests scroll to below-the-fold controls (`scrollUntilVisible`) — lazy ListView builds
  only near-viewport children.
